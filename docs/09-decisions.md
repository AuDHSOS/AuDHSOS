| D-68 | `net-wire` reads and writes one text per address and computes the internet checksum with the end-around carry applied to every word. Both are departures worth naming. The parse is the canonical form and nothing else: `010.0.0.1` is refused rather than read as ten or as eight, because a host that accepts both spellings can be shown one address by a check and another by a connection, and the same reasoning already made `audhsos-encoding` strict. A prefix length above 32 is `PrefixLength`, and a number above 255 after the slash is not a prefix length at all but a malformed text. The checksum departs from RFC 1071 section 2, which recommends letting the carries pile up in the high half of a wider accumulator and folding once at the end: `Checksum` folds at every word, so its accumulator is sixteen bits that provably never leave sixteen bits and every addition in the crate is a checked one under a lint profile that forbids an operation which could overflow. The deferred form is an optimization for hand-written assembly, and this crate is checked Rust on a path that carries at most an interface MTU per call. The accumulator also holds the odd byte a call ended on, so a caller may feed it a pseudo-header, a header, and a payload in any number of calls without an odd length shifting the words of the next one, which is what RFC 1071 section 2 (A) requires and what a transport checksum over three separate buffers needs. | decided | 2026-09-05 |
| D-69 | IPv6 is in the first network version beside IPv4, which supersedes the first clause of D-50; the rest of D-50 stands. `net-ipv6` joins the crate list of D-49 at layer n2 beside `net-ip`, which holds what the two families share — the routing table over `IpCidr`, the reassembly buffers, and the interface the transports send through — so that everything above n2 depends on `net-ip` alone and knows no family. The layers above the wire carry `IpAddr` and `IpCidr` and are written once for both families rather than twice, because the alternative is to widen eight crates and their tests after D8 rather than to write them wide. Three things follow and are decided here. The neighbor cache of `net-eth` is keyed by `IpAddr` and holds the states of RFC 4861, of which ARP's three are a subset; ARP fills its IPv4 half and Neighbor Discovery, which is `ICMPv6` and therefore sits above IP rather than beside it, fills the other, so the cache is driven from `net-ip` and not from the frame layer. Address configuration for IPv6 is the router advertisement of RFC 4861 with SLAAC and the recursive DNS server option of RFC 8106; there is no DHCPv6, because it is a second protocol of the size of `net-dhcp` for a capability the advertisement already carries.
